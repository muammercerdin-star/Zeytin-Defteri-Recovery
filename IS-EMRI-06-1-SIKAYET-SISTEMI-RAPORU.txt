GERÇEK VERİ MODELİYLE EŞLEŞME
Mevcut gönderi: social_posts/{postCloudId}, sahibi user_id.
Mevcut yorum/yanıt: social_posts/{postCloudId}/comments/{commentCloudId}, sahibi user_id.
parent_comment_id boşsa COMMENT, doluysa REPLY. Yerel post_comments.user_key ve cloud_id alanları mevcut kayıttan alınır. Yerel sayısal id Firestore hedef kimliği olarak kullanılmaz.
CommentManager.showComments zaten PostRepliesActivity açtığı için kullanılmayan eski yorum çizim kodu değiştirilmedi. SocialCloudRepository ve DatabaseHelper incelendi; raporların sosyal içerik senkronizasyonuna karışmaması için değiştirilmedi.

RAPOR KOLEKSİYONU / ALANLARI
Yol: reports/{reporterUid}/items/{reportId}
reports altında kullanıcıya göre yol ayrımı vardır; rapor belgeleri items alt koleksiyonundadır.
Alanlar:
- reporter_uid: Firebase Auth UID
- reported_uid: hedefin sahibi UID
- target_type: POST / COMMENT / REPLY / USER
- target_id: gönderi/yorum/yanıt cloud ID; USER için raporlanan UID
- post_cloud_id: kaynak gönderinin cloud ID'si
- comment_cloud_id: yorum/yanıt cloud ID; gönderiden raporda boş
- reason: SPAM / ABUSE / MISLEADING / INAPPROPRIATE / FRAUD / OTHER
- created_at: FieldValue.serverTimestamp(), rules tarafında request.time ile eşitlik
- status: OPEN
USER raporunda kaynak gönderi/yorum bilgisi kanıt bağlamı olarak tutulur; rules sahibini oradan doğrular. Yeni kullanıcı/profil verisi veya sosyal içerik üretilmez.

DUPLICATE KORUMASI
İçerik anahtarı: target_type + | + post_cloud_id + | + target_id
Kullanıcı anahtarı: USER||reported_uid
Raporlayan UID üst yolda sabittir. Aynı kullanıcı farklı gönderi veya yorumdan aynı üreticiyi raporlasa bile aynı USER belgesine gider. Sebep değiştirmek yeni belge üretmez. Kimlik doğrulayıcı yalnızca uygulamadaki UUID/Firebase UID biçimine uygun A-Z/a-z/0-9/alt çizgi/tire, 1–128 karakter kabul eder; ayraç ve slash reddedilir.
Transaction önce aynı belgeyi okur; varsa duplicate mesajı döner. Yoksa oluşturur. Eşzamanlı transaction yeniden denemesinde de ikinci kayıt oluşmaz. Rules deterministik belge adını zorunlu tutar ve update/delete işlemlerini reddeder.
İstemci açısından bir kullanıcı/hedef için mevcut rapor varken ikinci rapor açılamaz; CLOSED olsa bile tekrar açma yetkisi yoktur. İleride yeniden açma politikası admin/backend işidir.
